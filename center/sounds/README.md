# Звук объекта

Записи лежат здесь, у центра: у него акустика зала и он же решает,
когда что звучит. Сборщики о звуковых файлах не знают вовсе — они
щёлкают реле, и держать записи ещё и у них значило бы следить, чтобы
три копии не разошлись.

Формат любой, какой понимает ffmpeg: wav, mp3, ogg, flac, m4a, opus.
Имя файла задаёт назначение, расширение — нет:

| Файл | Когда звучит |
|---|---|
| `alarm` | аварийная остановка: «Аварийная остановка. Просим покинуть помещение тренировки» |
| `success` | занятие выполнено: «Пострадавший спасён. Тренировка выполнена успешно» |
| `sound` | фоновые эффекты зала — крики о помощи. Крутятся по кругу, пока узел «Аудиоэффекты» включён |

Если в зале должна звучать своя запись, положите файл с приставкой
помещения — он имеет приоритет над общим:

```
room-2-sound.mp3     эффекты первого этажа дымокамеры
room-3-sound.mp3     эффекты второго этажа
alarm.mp3            общее оповещение для всех залов
```

Одна и та же запись дважды разом не звучит: аварию объявляют по всем
помещениям сразу, и общая фраза наложилась бы сама на себя втрое.
Там, где у помещения своя запись, файлы разные — звучат оба.

Проигрывает ffmpeg — он уже в образе ради видеотракта. Каталог
задаётся переменной `MCHS_SOUNDS`; пусто — звука на объекте нет, и
центр о нём молчит.

По умолчанию звук идёт прямо в ALSA: на объекте звуковая карта
свободна. На машине, где её держит звуковой сервер (PipeWire,
PulseAudio), карта занята им, и путь идёт через его сокет — в `.env`:

```
MCHS_PULSE_SOCKET=/run/user/1000/pulse/native
PULSE_SERVER=unix:/run/pulse-native
MCHS_SOUND_PLAYER=ffmpeg -hide_banner -loglevel error %loop% -re -i %s -f pulse mchs
```

На объекте эти три строки убираются.

Звуковое устройство пробрасывается в контейнер в `compose.yaml`
(`/dev/snd` и группа `audio`). Проверить, что центр его видит:

```bash
docker compose exec center sh -lc 'ls /dev/snd'
```
