# Контракт стойки набора чисел

Согласован и закреплён тестами (`stand_test.go`): строки в этом
документе — ровно те, что собирает прошивка `firmware`, и команды в
том виде, в каком их принимает её разборщик. Расхождение ломается на
тесте, а не в зале: стойка стоит в задымлённом помещении, её не видно
и не слышно, и обнаружилось бы оно на занятии — когда звено упрётся в
задание, которое не засчитывается.

Остальной контракт — в `ARCHITECTURE.md` §2.1; здесь только стойка.

## Что делает плата

Отвечает на один вопрос: набранный код верен или нет. Ничего не
разблокирует и ничем не управляет — что делать с ответом, решает
центр (сценарий дымокамеры §4).

Набранный код **не передаётся никогда** — ни в сеть, ни в консоль.
Вводят его на виду у людей, и протокол не место для набранных цифр.
Эталон на плате хранится хешем, а не текстом.

## Телеметрия: плата → сборщик

UDP на порт сборщика, JSON, поля по `telemetry.Telemetry`.

Нажатие клавиши. Уходит на каждое нажатие, включая цифры: по нему
видно, что стойкой пользуются, даже когда код ещё не добран.

```json
{"event":"key","key":"7","uptime_ms":123456}
```

Результат проверки кода. Уходит только по подтверждению набора:

```json
{"event":"code","code_result":"valid","uptime_ms":123456}
```

| `code_result` | Что произошло | Как понимает центр |
|---|---|---|
| `valid` | код верен | задание «Набор чисел» засчитано |
| `invalid` | код неверен | попытка, задание не засчитано |
| `locked` | пауза после трёх неудач подряд | не попытка; видно оператору |
| `cleared` | набранное стёрто клавишей сброса | не попытка |

Попытками считаются только `valid` и `invalid`. Стирание и пауза —
нет: иначе человек, сбросивший случайное нажатие, выглядел бы в
отчёте подбиравшим код.

Очередной отчёт о себе, без показаний. Измерять стойке нечего, но
молчать нельзя: замолчавшее устройство сборщик считает пропавшим, а
по падению `uptime_ms` видно, что плата перезапустилась, — сборщик по
этому признаку досылает уставки.

```json
{"uptime_ms":123456}
```

## Команды: сборщик → плата

На тот же порт, с которого уходит телеметрия. Пары ключ=значение
через пробел, без JSON: разбор JSON на плате стоит дороже, чем весь
командный тракт.

```
cmd=set_code id=a1b2c5 seq=9 code=4731
cmd=set_period id=a1b2c6 seq=10 period_ms=200
```

| Команда | Поля | Проверка на плате |
|---|---|---|
| `set_code` | `code` — от 3 до 12 цифр | негодный код отвергается, прежний продолжает действовать |
| `set_period` | `period_ms` — от 50 до 60000 | вне диапазона отвергается |

Команды, адресованные другим устройствам — пушке, препятствиям, узлам
помещения, — плата не исполняет и не подтверждает.

Повтор команды с тем же `id` подтверждается, но второй раз не
применяется: сборщик переотправляет, не дождавшись ответа, а смена
кода повторно — это новый код посреди набора. Команда с `seq` меньше
последнего исполненного отвергается как устаревшая.

## Подтверждение: плата → сборщик

```
ack=a1b2c5 ok=1 state=ok reason=ok uptime_ms=123456
ack=a1b2c6 ok=0 state=ok reason=bad_code uptime_ms=10
```

`ok=0` — осознанный отказ, а не потеря команды; причина в `reason`:

| `reason` | Когда |
|---|---|
| `ok` | исполнено |
| `duplicate` | повтор уже исполненной команды |
| `stale_seq` | команда из прошлого |
| `bad_code` | код не прошёл проверку |
| `out_of_range` | период вне диапазона |
| `unknown` | вид команды плате неизвестен |

## Пределы

| | Плата | Центр |
|---|---|---|
| длина команды | `COMMAND_MAX_LEN` 160 | `MaxCommandLen` 160 |
| длина кода | `CODE_MAX_LEN` 12 | `MaxCodeLen` 12 |
| минимум цифр | 3 | `MinCodeLen` 3 |
| идентификатор команды | `COMMAND_ID_LEN` 17 с нулём | 16 символов |

## Что остаётся за кадром

Какая клавиатура стоит на стойке — плёночная (`*` и `#`) или
шестнадцатеричная (`0-9`, `A-F`). На второй нет клавиш подтверждения
и сброса, и они назначены на `E` и `F`. Прошивка собирается в обоих
вариантах, на контракт это не влияет: наружу уходит результат, а не
клавиша.
