# Пульт управления тренажёрным комплексом

Служба отдельного Raspberry Pi с физическими кнопками: три расширителя
MCP23017 на шине I²C, по микросхеме на помещение, плюс общий аварийный
грибок.

## Как это устроено

```
пульт ──▶ центр ──▶ сборщики помещений (room1, room2, room3)
  └──────── авария, когда центр молчит ────────▶
```

Обычная кнопка **всегда** идёт через центр. Там живут сценарий
подготовки, журнал, состав смены и состояние — второй путь с другими
проверками рано или поздно разошёлся бы с первым в поведении. Поэтому
пульт входит в центр обычной учётной записью оператора и дёргает тот
же API, что и панель: помещение можно вести и с пульта, и из панели,
и они не спорят.

Мимо центра ходит только аварийная остановка, и только когда центр не
ответил: останавливать зал нельзя ставить в зависимость от одного узла.
В этом случае пульт стучится прямо в сборщики, а затем добивается,
чтобы авария попала и в центр — по журналу разбирают происшествие.

Сценария на пульте нет. Что включается при старте подготовки и что
остаётся включённым в аварии, решает центр.

## Лампы говорят правду

Лампа у кнопки загорается **не по нажатию**, а когда сборщик помещения
отчитался, что реле действительно щёлкнуло. Пока подтверждения нет,
лампа мигает. Нет связи с центром — лампы гаснут все: показывать
последнее известное состояние опаснее, чем не показывать ничего.

Для этого центр различает «команда ушла» и «реле щёлкнуло»: у узла
есть подтверждённое состояние и ожидание. То же самое видно и в
панели — «включается…» вместо мгновенного «работает».

## Раскладка

Кнопки на порту A (вход, подтяжка к питанию, замыкание на землю),
лампы на порту B (выход). Адрес микросхемы задаётся её ногами
A0/A1/A2: 0x20 — все на землю, 0x21 — A0 на питание, 0x22 — A1,
0x24 — A2. Адреса в таблице — те, что распаяны на объекте: вторая
микросхема сидит на 0x24, и раскладка подогнана под провода, а не
наоборот.

| Помещение | Адрес | Кнопки |
|---|---|---|
| Теплокамера | 0x20 | тепловая пушка, освещение, вытяжка, бесконечная лестница |
| Дымокамера, 1 этаж | 0x24 | дымогенератор, тепловая пушка, прожекторы, стробоскоп, освещение, вытяжка |
| Дымокамера, 2 этаж | 0x22 | дымогенератор, тепловая пушка, стробоскоп, освещение, вытяжка, завалы |

Аварийный грибок сидит на свободных ногах первой микросхемы: кнопка
A7, лампа B7. Грибок **нормально замкнутый** — в покое цепь целая,
нажатие её размыкает. Обрыв провода выглядит как нажатие: отказ в
безопасную сторону, так и задумано.

Имена узлов (`unit`) должны совпадать с `rooms.yaml` центра буква в
букву: расхождение означает кнопку, которая молча ничего не делает.

## Устройство в сети

| | |
|---|---|
| Имя хоста | `rpi_pult` (в ряду со сборщиками `rpi_room1…3`) |
| Адрес | 192.168.1.13, шлюз 192.168.1.1 |
| Пользователь карты | `pult`, вход по ключу, пароль для консоли задаётся при подготовке |
| Учётная запись в центре | `pult`, роль оператора |
| Служба | `mchs-pult`, работает под пользователем `mchs` |

Карта готовится до того, как узел появится в сети: ansible требует
SSH, а SSH требует настроенной карты.

```bash
sudo PASS='<пароль консоли>' \
     PULT_PASS='<пароль в центре>' \
     PULT_ALARM_TOKEN='<секрет аварии>' \
     tools/provision-card.sh
```

Скрипт ставит статический адрес, имя хоста, пользователя с ключом,
включает I²C, кладёт бинарь, раскладку и секреты, включает службу.
Пароль консоли на карту попадает только хешем, в репозиторий — никогда.
Повторный запуск безопасен.

## Запуск

```bash
make test          # логика кнопок проверяется без железа
make build-arm64   # бинарь под RPi
make deploy        # перенос на устройство
```

Выкладке нужны два секрета, и в репозиторий они не пишутся:

```bash
export PULT_PASS=...          # пароль учётной записи pult в центре
export MCHS_ALARM_TOKEN=...   # секрет прямой аварии, тот же, что у сборщиков
```

На устройстве они лежат в `/etc/mchs/pult.env` с правами `0640`, а в
раскладке стоят только ссылки на переменные.

Со стороны сборщиков тот же секрет задаётся переменной
`MCHS_ALARM_TOKEN` при их выкладке. Пустое значение выключает приём
аварии напрямую — тогда остановка ходит только через центр.

## Проверка на месте

```bash
sudo /opt/mchs/bin/pultd -probe        # какие расширители отзываются
journalctl -u mchs-pult -f             # нажатия и ответы центра
```

В журнале каждое нажатие видно строкой `кнопка пульта`, а отказ —
причиной: нет связи, помещение в аварии, узел ещё ждёт подтверждения.
