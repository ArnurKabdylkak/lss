# Готовые прошивки стойки набора чисел

Собраны из этого дерева, контракт сведён с центром и закреплён
тестами (`telemetry/CONTRACT-STAND.md`, `stand_test.go`).

## Стойка набора чисел

| Файл | Клавиатура | Подтвердить | Стереть |
|---|---|---|---|
| `code_room2.bin` | плёночная: `1-9`, `*`, `0`, `#`, столбец `A-D` | `#` | `*` |
| `code_room2_hex.bin` | шестнадцатеричная: `0-9`, `A-F` | `E` | `F` |

Обе — для стойки дымокамеры, первый этаж: плата `192.168.1.60`,
сборщик `192.168.1.11`. Остальное у них одинаково.

## Имитатор очага

| Файл | Куда | Плата | Сборщик |
|---|---|---|---|
| `fire_room2.bin` | дымокамера, 1 этаж | 192.168.1.61 | 192.168.1.11 |
| `fire_room3.bin` | дымокамера, 2 этаж | 192.168.1.73 | 192.168.1.12 |

Подключение одинаковое:

```
PD14 (D10)  ->  вход реле (IN)     единица включает нагрузку
PF12 (D8)   ->  кнопка тушения     замыкание на землю
```

Очаг горит с момента включения платы и гаснет только кнопкой. Сам он
не возвращается: зажигает его старт подготовки помещения командой
центра. Иначе очаг вспыхивал бы за спиной у звена, которое его уже
потушило, и задание засчитывалось бы дважды.

Красный светодиод платы повторяет состояние очага — видно, не
подходя к зеву.

Какую заливать, решает то, какая клавиатура смонтирована. Если
неизвестно — залейте плёночную и нажмите подтверждение: если набор
не засчитывается, а в консоли видно `key=E`, значит стоит
шестнадцатеричная.

## Как залить

```bash
pio run -e code_room2 -t upload        # или code_room2_hex
```

Либо готовым файлом, без пересборки:

```bash
st-flash --reset write firmware/code_room2.bin 0x8000000
```

## Как проверить на месте

Консоль платы — USART3 на ST-Link, 115200:

```
Стойка набора чисел (STM32F767)
Local 192.168.1.60 -> server 192.168.1.11:5005
key=4
key=7
code=valid
набрано=0  link=up
```

`link=up` — поднят линк и настроен интерфейс. `набрано=N` — сколько
цифр введено сейчас; сами цифры не печатаются нигде.

Со стороны центра: при старте подготовки дымокамеры формируется код
занятия, он виден в окне помещения и уходит на стойку командой
`set_code`. Верный набор засчитывает задание «Набор чисел» в маршруте.

## Ударный молот

| Файл | Куда | Плата | Сборщик |
|---|---|---|---|
| `load_room1.bin` | теплокамера | 192.168.1.50 | 192.168.1.10 |

Подключение:

```
PF12 (D8)  ->  геркон      замыкание на землю
```

Магнит на подвижной части проходит мимо геркона дважды за полный
цикл — на замахе и на возврате. Повторением считается каждое второе
срабатывание: иначе зачёт оказался бы вдвое щедрее работы.

Счётчик накопительный и между заходами не обнуляется. Результат
захода центр считает приростом: он запоминает показания при
назначении человека на тренажёр и вычитает их в конце. Поэтому
перезапуск платы посреди смены виден как падение счётчика, а не как
выполненная норма.

Зелёный светодиод платы моргает на каждом засчитанном повторении —
видно, считает ли она, не отходя от тренажёра. В консоли:

```
повторений=12  проходов=24  link=up
```

Расхождение между ними вдвое — норма. Если проходов нечётное число и
повторения встали, магнит не доходит до геркона на обратном ходу.
