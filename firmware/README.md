# firmware — стойка набора чисел

Прошивка PlatformIO для STM32F767ZI на libopencm3: матричная клавиатура,
проверка кода и отчёт в сборщик помещения по UDP через lwIP.

Плата отвечает ровно на один вопрос: набранный код верен или нет.
Ничего не разблокирует и ничем не управляет — что делать с ответом,
решает центр (сценарий дымокамеры §4). Оборудование зала — дым, свет,
замки — висит на сборщике помещения: решение исполняет тот, у кого реле.

## Распиновка

| Назначение | Выводы |
|---|---|
| Клавиатура, строки (выходы) | PE11 (D5), PE13 (D3), PF14 (D4), PF15 (D2) |
| Клавиатура, столбцы (входы с подтяжкой) | PE9 (D6), PF13 (D7), PF12 (D8), PD15 (D9) |
| Ethernet RMII | PA1 REF_CLK, PA2 MDIO, PA7 CRS_DV, PC1 MDC, PC4 RXD0, PC5 RXD1, PG11 TX_EN, PG13 TXD0, PB13 TXD1 |
| USART3 (ST-Link VCP, 115200) | PD8 TX, PD9 RX |
| Светодиод «код принят» | **PD14 (D10)** — внешний зелёный на стойке, горит 5 с после верного набора |
| Светодиоды платы | PB0 — идёт набор; PB7 — поднят линк |

Разводка снята с объекта режимом поиска, не взята из описания: у
матричных клавиатур порядок выводов у каждой модели свой, а шлейф на
этой стойке к тому же воткнут зеркально — строки оказались там, где
обычно столбцы.

```
          PE9    PF13   PF12   PD15     <- столбцы (D6, D7, D8, D9)
 PE11      1      2      3      A
 PE13      4      5      6      B
 PF14      7      8      9      C
 PF15      *      0      #      D
   ^ строки (D5, D3, D4, D2)
```

Если клавиатуру заменят, снимите разводку заново:

```bash
pio run -e discover -t upload     # режим поиска
```

Удерживайте клавиши по одной — плата напечатает в консоль, какая пара
ног замкнулась. Потом залейте обратно рабочую прошивку.

## Клавиатура и раскладка

По умолчанию — обычная плёночная матрица:

```
1 2 3 A
4 5 6 B
7 8 9 C
* 0 # D
```

Цифры накапливаются, `#` проверяет набранное, `*` стирает.

Если на стойке стоит шестнадцатеричная клавиатура (0–9, A–F), на ней
нет «решётки» и «звёздочки», и подтверждать набор нечем. Для неё есть
отдельное окружение: подтверждение назначено на `E`, стирание на `F`.

## Светодиод «код принят»

Зелёный светодиод на самой стойке, на ноге **PD14 (D10)**. Загорается
на пять секунд, когда набран верный код, и гаснет сам.

```
PD14 (D10) ──[ 330 Ом ]──┤>├── GND
                          анод  катод
```

Нога свободна и не пересекается ни со строками клавиатуры
(D5, D3, D4, D2), ни со столбцами (D6, D7, D8, D9), ни с линиями
Ethernet. Выход отдаёт до 20 мА — обычного светодиода хватает с
запасом.

Зажигается он на плате, не дожидаясь ответа центра: человеку у стойки
нужен ответ здесь и сейчас, а связь может моргнуть. Светодиоды самой
платы при этом оставлены как были — LD1 показывает, что идёт набор,
LD2 что поднят линк; но смотреть на контроллер в щите из задымлённого
зала некому, для того и вынесен отдельный.

## Проверка кода

- Эталон хранится хешем FNV-1a, а не открытым текстом: в дампе памяти
  или прошивки кода не окажется.
- Сам набранный код не уходит в сеть и не печатается в консоль никогда
  — только результат. Вводят его на виду у людей.
- Недобранный код стирается сам через 15 с, иначе цифры, набранные
  кем-то раньше, допишутся к новому вводу.
- Три неудачи подряд придерживают ввод на 30 с: четырёхзначный код
  иначе подбирается за считаные минуты.

## Сеть

lwIP в режиме `NO_SYS=1`, статический адрес, UDP. Телеметрия уходит на
сборщик помещения, команды приходят на тот же порт. Подтверждение
отправляется тому, кто прислал команду, а не по адресу из настроек:
сборщик может стоять не там, куда уходит телеметрия.

Команды приходят парами ключ=значение, без JSON — его разбор на плате
стоит дороже, чем весь командный тракт:

```
cmd=set_code id=a1b2c5 seq=9 code=4731
cmd=set_period id=a1b2c6 seq=10 period_ms=200
ack=a1b2c5 ok=1 state=ok reason=ok uptime_ms=123456
```

Команды, адресованные другим устройствам (пушка, препятствия, узлы
помещения), плата не исполняет.

Измерять стойке нечего, но молчать нельзя: раз в период отчёта уходит
`{"uptime_ms":…}`. Замолчавшее устройство сборщик считает пропавшим, а
по падению `uptime_ms` видно, что плата перезапустилась.

## Адреса

Адрес платы и её сборщика задаются окружением сборки, а не в исходнике:
плат на объекте несколько, они стоят в разных помещениях, а прошивка у
них одна.

| Окружение | Плата | Сборщик | Клавиатура |
|---|---|---|---|
| `code_room2` | 192.168.1.60 | 192.168.1.11 | плёночная |
| `code_room2_hex` | 192.168.1.60 | 192.168.1.11 | 0–9, A–F |
| `nucleo_f767zi` | 192.168.1.50 | 192.168.1.10 | плёночная, стенд |

```bash
pio run -e code_room2 -t upload
```

## Тесты

Логика, не зависящая от железа, проверяется на хосте — заголовки
libopencm3 подменяются заглушками:

```bash
make -C test/host run
```

Двадцать проверок: набор и стирание, тайм-аут, пауза после подбора,
смена кода командой, повторы и порядок команд, отказ от чужих команд,
переполнение буфера.
